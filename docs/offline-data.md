# 離線環境怎麼更新官方資料

官方弱點資料每天都可能更新。離線環境不能直接下載，所以做法一律是：**在能上網的電腦下載，帶進離線環境，核對後再用。**

## 下載工具時就有一份

為了避免進到封閉環境才發現沒有資料，本專案在 GitHub 上每天自動更新一份官方資料：

| 放在哪裡 | 怎麼拿到 |
|---|---|
| `data` 分支（只保留最新一份，不累積歷史） | 一般的 `git clone` 會一起下載。`hc` 第一次執行時自動放進 `data/`，不需要網路。之後執行 `git pull` 就會帶回最新的一份 |
| Releases 的 `data-latest` | `Ubuntu-Server-Audit-full.zip`：工具加最新資料，解壓後即可使用，適合沒有 git 的電腦 |

注意：GitHub 網頁上的「Download ZIP」，以及 `git clone --depth 1`、`--single-branch`，都拿不到 `data` 分支。

這份資料由 GitHub Actions 每天台灣時間 11:17 左右從 Canonical 官方網站下載，檢查內容完整才發布，檔案沒有修改過。官方下載失敗的那天不會更新，保留前一天的版本。`SOURCES.json` 記著每個檔案的官方網址與下載時間。

只能連 GitHub、連不到 Canonical 時，也可以用 `./hc update --from github` 下載這份副本，下載後一樣核對 SHA-256 與內容。

## 先決定分析電腦放在哪裡

| 情況 | 分析電腦放哪裡 | 官方資料要不要帶進受檢單位 |
|---|---|---|
| 收集檔可以帶出受檢單位 | 執行人員自己的電腦（可上網） | 不用。出發前一天更新資料，回來再分析 |
| 收集檔不能帶出受檢單位 | 受檢單位離線網段內的一台電腦 | 要。依下面「手動匯入」帶進去 |

不論哪種情況，官方資料都只放在分析電腦，**不必放進受檢主機**。

## 自動更新（能上網的電腦）

`./hc update` 會先問官方伺服器檔案有沒有更新，沒更新就不重複下載，所以可以放心每天排程執行。

Linux 用 cron 每天早上 6 點更新（路徑請換成實際位置）：

```
0 6 * * * cd /opt/Ubuntu-Server-Audit && ./hc update --quiet
```

`--quiet` 只在出錯時輸出訊息。需要經過 Proxy 時，在排程裡設定 `https_proxy` 環境變數。

## 手動匯入（帶進離線環境）

1. 在能上網的電腦執行：

   ```bash
   ./hc update
   ```

2. 把整個 `data/` 資料夾複製到隨身碟，或走受檢單位規定的媒體匯入程序（例如掃毒、單向傳輸設備）。資料夾內有：
   - `oci.com.ubuntu.<代號>.usn.oval.xml.bz2`：官方原始檔，沒有經過任何修改
   - `SOURCES.json`：下載網址、官方更新時間、下載時間、SHA-256
   - `SHA256SUMS`：雜湊值清單

3. 在離線的分析電腦上核對：

   ```bash
   ./hc update --verify
   ```

   或用系統內建指令：

   ```bash
   cd data && sha256sum -c SHA256SUMS
   ```

   全部顯示「一致」或 `OK` 才使用。只要有一個不一致，就重新下載再帶一次。

4. 要更嚴謹時，可以在下載當下把 `SHA256SUMS` 的內容另外記錄下來（例如印出或寫進交接單），匯入後再拿來比對。這樣能確認雜湊值清單本身在搬運途中也沒被換掉。

## 改用自己保管的資料

資料不一定要放在程式旁的 `data/`。放在任何資料夾都可以，掃描時加上 `--data`：

```bash
./hc report hc-H01-*.tar.gz --data /media/usb/oval
```

只想用某一個檔案時，改用 `--oval 檔案路徑`。

## 不用本工具也能下載

在瀏覽器打開 <https://security-metadata.canonical.com/oval/>，下載需要的版本，檔名開頭必須是 `oci.`。例如 20.04 是 `oci.com.ubuntu.focal.usn.oval.xml.bz2`。

這樣下載的檔案沒有 `SOURCES.json`，報告的「與下載紀錄」欄會顯示「無紀錄」，但比對照常進行。

版本代號：14.04 trusty、16.04 xenial、18.04 bionic、20.04 focal、22.04 jammy、24.04 noble、26.04 resolute。

## 資料多新才算夠新

開始收集前，工具會先檢查官方資料的日期。分析完成後，畫面摘要會列出這次用到的各版本資料是哪一天產生的，例如：

```
官方資料：focal（20.04），產生於 2026-11-15（1 天前），雜湊核對：一致
```

超過規則檔的 `data_max_age_days`（預設 7 天），或缺少某個版本的資料時，會問你要不要先更新；報告上也會出現警告。不想被問，可以加 `--update no`（不更新）或 `--update yes`（自動更新）。

分析電腦能上網時，可以在 `scan`、`report`、`local` 後面加 `--refresh-data`：開始收集前先向 Canonical 檢查這次要用的版本有沒有新資料，有就下載（沒變的不會重抓）。每次連線最多等 15 秒；連不上就停止檢查，改用已下載的資料，掃描照常進行。不論有沒有加，開始收集前畫面都會說明這次用的資料來源與時間點，例如：

```
本次使用的官方弱點資料（data）：
  noble（24.04）：官方產生於 2026-11-18（1 天前），剛從 Canonical 更新
  focal（20.04）：官方產生於 2026-11-12（7 天前），無法連線，改用已下載的資料
```

`scan` 在收集前還不知道每台主機的版本，所以只檢查已經下載過的版本；收集後才發現缺少的版本，連得上時會直接下載。

天數可以在自訂規則檔裡調整，見 [custom-rules.md](custom-rules.md)。

## 官方資料的可信度怎麼確認

- 來源固定是 `https://security-metadata.canonical.com/oval/`，程式透過 HTTPS 下載，並檢查憑證。
- 下載後會確認檔案能完整解壓、是 OVAL 格式，而且是套件清單版。
- Canonical 目前沒有為這些檔案另外提供數位簽章，所以「搬運途中沒被改過」只能靠下載當下留下的 SHA-256 來核對。
- 從 GitHub 副本取得的檔案，`SOURCES.json` 會多記一個 `copied_from`。在意來源的單位，建議能連官方網站時改用 `./hc update` 直接向 Canonical 下載。
