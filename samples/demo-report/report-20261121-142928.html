四、建議處理順序

  1. 當天就能改、不用採購的高風險設定（demo-ap01）：SSH 允許 root 直接登入。
  2. 安裝已經可以取得的安全修補（demo-db01、demo-web01、demo-ap01）：在主機上執行 sudo apt update 與 sudo apt upgrade；含核心更新的要排時段重開機。只想先修重大與高風險時，見各主機的「重大與高風險公告」。
  3. 要訂閱 Ubuntu Pro 才拿得到修補的主機（demo-db01、demo-web01、demo-ap01）：評估訂閱 Ubuntu Pro 取得這些修補；已過標準維護期的主機，同時排定升級計畫。
  4. 修補要重開機才生效的主機（demo-db01、demo-web01、demo-ap01）：排定重開機時段；停機困難的，評估 Livepatch（只處理高風險與重大核心漏洞，不能取代所有重開機）。
  5. 其他設定與管理項目（demo-db01、demo-web01、demo-ap01）：SSH 允許密碼登入、未啟用自動安全更新、非 Ubuntu 官方來源的套件、主機防火牆（ufw）未啟用，依各項的建議排入例行維護。
  6. 需要設定基準的稽核證據時（demo-web01、demo-ap01）：評估 Ubuntu Pro 內含的 USG，並與適用的組態基準比對。
  7. 有項目未能檢查（demo-web01）：收集時權限不足或缺資料，不代表沒有問題；可加 --sudo 重新收集，或依各主機的說明補資料。

五、檢查範圍與限制

  • 本健檢只讀取系統資訊，不做弱點利用測試、不修改設定，不等同滲透測試。
  • 只涵蓋 Ubuntu 官方套件庫的套件；第三方軟體（例如自行安裝的應用程式）的弱點不在比對範圍。
  • 官方弱點資料以「已安裝的套件版本」比對：舊核心套件若仍留在系統上，也可能被列入；實際執行中的核心請看 B 類。
  • 建議欄的指令是一般做法，執行前請依單位的變更管理規定評估，並先在測試環境確認。
  • 標示「未能檢查」的項目，代表收集時權限不足或主機沒有對應工具，不代表沒有問題。
  • 結果反映收集當下的狀態，以及報告上所列官方資料日期之前公布的弱點。
